# WIKI Schema & Conventions

ไฟล์นี้คือ **กติกา** ของวิกิ — บอก LLM ว่าวิกินี้จัดระเบียบยังไง และต้องทำอะไรตอน
ingest / query / lint. อ่านไฟล์นี้ก่อนเสมอเมื่อเริ่ม session ใหม่.

> หลักการ: **LLM เป็นเจ้าของโฟลเดอร์ `wiki/` ทั้งหมด** มนุษย์อ่านและชี้ทิศ
> ส่วนโค้ดจริง (`client/`, `server/`) คือ source of truth ที่อ่านอย่างเดียว ห้ามแก้เพื่อทำวิกิ.

## ขอบเขต

วิกินี้สรุป **สถาปัตยกรรมและความรู้เชิงระบบ** ของโปรเจกต์ SmartEE Web
(ไม่ใช่ที่เก็บ requirement หรือ task tracker). เป้าหมายคือให้ตอบได้เร็วว่า
"ระบบทำงานยังไง / ทำไมถึงทำแบบนี้ / แก้ตรงไหน" โดยไม่ต้องไล่อ่าน `index.js` 6,000+ บรรทัดทุกครั้ง.

⚠️ **หมายเหตุสำคัญ:** ไฟล์ `C:\Workspaces\CLAUDE.md` อธิบายโปรเจกต์ชื่อ *SmartCatcherPro*
(monorepo + TimescaleDB + JWT) ซึ่ง **ไม่ตรง** กับโปรเจกต์นี้ (SmartEE = client/server + SQL Server + custom token).
ยึดวิกินี้และโค้ดจริงเป็นหลักเสมอ.

## โครงสร้างโฟลเดอร์

```
wiki/
├── WIKI.md            # ไฟล์นี้ — schema/กติกา
├── index.md           # สารบัญทุกหน้า (อัปเดตทุกครั้งที่ ingest)
├── log.md             # บันทึกตามเวลา (append-only)
├── architecture/      # ภาพรวมระบบ + flow หลัก
├── db/                # โครงสร้างฐานข้อมูล + convention
├── decisions/         # ADR — บันทึกการตัดสินใจเชิงสถาปัตยกรรม
└── gotchas.md         # กับดัก/บั๊ก/ข้อควรระวังที่เคยเจอ
```

## รูปแบบหน้า (page format)

ทุกหน้าเริ่มด้วย frontmatter:

```yaml
---
title: <ชื่อหน้า>
tags: [api, auth, db, realtime, ...]
updated: YYYY-MM-DD
sources:            # ลิงก์ไปโค้ดจริงเสมอ (path:line)
  - server/index.js:76
  - server/utils/crypto.js
---
```

## กติกาการเขียน

- **ภาษาไทย** เป็นหลัก แต่ศัพท์เทคนิค/ชื่อตาราง/ชื่อฟังก์ชันคงภาษาอังกฤษ.
- อ้างอิงโค้ดด้วย `path:line` เสมอ เช่น `server/index.js:137` — คลิกได้.
- โยงหน้าอื่นด้วย `[[wikilink]]` โดยใช้ชื่อไฟล์ (ไม่ต้องใส่ `.md`) เช่น `[[auth-and-permissions]]`.
- เมื่อข้อมูลใหม่ขัดแย้งของเก่า → ใส่ callout `> ⚠️ CONTRADICTION (YYYY-MM-DD): ...` แทนการลบทิ้งเงียบ ๆ.
- เขียนให้คนที่ไม่เคยเห็นโค้ดอ่านรู้เรื่อง — อธิบาย "ทำไม" ไม่ใช่แค่ "อะไร".

## Workflow: Ingest (รับความรู้เข้าวิกิ)

เมื่อ user สั่ง "ingest <เรื่อง/PR/ไฟล์>":
1. อ่าน source จริง (โค้ด / diff / เอกสาร).
2. สรุปประเด็นสำคัญให้ user ฟังสั้น ๆ ก่อนเขียน.
3. สร้าง/อัปเดตหน้าที่เกี่ยวข้อง (หนึ่งเรื่องอาจแตะหลายหน้า).
4. อัปเดต `index.md`.
5. เพิ่ม 1 บรรทัดใน `log.md` ขึ้นต้นด้วย `## [YYYY-MM-DD] ingest | <หัวข้อ>`.

## Workflow: Query (ถามคำถามกับวิกิ)

1. อ่าน `index.md` ก่อนเพื่อหาหน้าที่เกี่ยวข้อง.
2. เปิดหน้านั้น → ถ้าจำเป็นเปิดโค้ดจริงตาม `sources:` เพื่อยืนยันว่ายังไม่ stale.
3. ตอบพร้อม citation (`path:line` + ชื่อหน้าวิกิ).
4. ถ้าคำตอบมีค่า (เปรียบเทียบ/วิเคราะห์/แผน) → เสนอ file กลับเป็นหน้าใหม่.

## Workflow: Lint (ตรวจสุขภาพวิกิ)

หาและรายงาน:
- **Contradiction** — สองหน้าพูดไม่ตรงกัน.
- **Stale** — หน้าอ้าง `path:line` ที่โค้ดเปลี่ยน/ลบไปแล้ว (เช็คกับ git/โค้ดจริง).
- **Orphan** — หน้าที่ไม่มีใครลิงก์ถึง.
- **Missing** — concept ที่ถูกพูดถึงบ่อยแต่ยังไม่มีหน้าของตัวเอง.
- เสนอคำถาม/แหล่งข้อมูลใหม่ที่ควรเพิ่ม.
